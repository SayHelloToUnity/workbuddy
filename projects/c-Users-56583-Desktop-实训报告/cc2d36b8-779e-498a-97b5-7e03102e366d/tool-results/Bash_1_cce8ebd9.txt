doc_apply_named_style                    把已有文字挂到指定的命名样式（DOC）。兼容旧参数 named_style_type，也支持显式传 target_style_id 或 target_style_name；三者必须且只能传一个。若传 target_style_name 且文档内存在重复显示名，沿用现有样式查询行为，使用第一个匹配项；通过 doc_register_named_styles 注册的样式不会产生重名。支持 paragraph_ids 或 ranges 二选一定位；一次请求批量应用同一个目标样式。目标是段落样式时：先清除段落直接格式（run 属性 + 段落覆盖），再设 pStyle。目标是字符样式时：只清除 range 内 run 直设，再写 rStyle，不动 pPr。【示例】{"target_style_id":"PaperFmt_ZhengWen","ranges":[{"begin":1187,"end":1350}]}
doc_batch_execute                        按「块清单」一次性写入内容（DOC）。一个块 = 1 个插入调用 + N 个作用于该块的操作调用，服务端按顺序执行并自动推导全部定位参数：
doc_clear_format                         一键清除指定范围内所有直设格式（DOC），重置为继承样式。同时清除 Run 层（加粗/斜体/下划线/删除线/字号/字体/颜色/高亮/上下标等）和段落层（对齐/缩进/间距/标题级别/边框等）的直设格式。
doc_compare_documents                    对比两个已打开的 DOC 文档的内容和格式差异。返回段落级别的差异列表，包括新增/删除/内容修改/格式修改。两个文档必须都已通过 open_file 打开。当前文档作为基准（source），通过 other_file_id 指定对比目标（target）。差异类型：added（目标新增）、deleted（源文档删除）、modified_content（内容变化）、modified_format（格式变化，如对齐方式、标题级别、段落样式等）。还支持对比页眉页脚、文本框（textbox/代码块/高亮块）、表格、批注和页面设置（页边距/页面尺寸）的差异。文本框对比：返回 textbox_diffs 字段，每项包含 type（code_block/highlight_block/textbox）标识类型，即使两个文档中同一位置的代码块 placeholder ID 不同也能按位置匹配识别为同一个代码块的内容修改。表格以原子单元对比：返回 table_diffs 字段，diff_type 包括 added/deleted/modified（维度不同）/modified_content（维度相同但单元格内容不同）/modified_format（维度和内容相同但单元格格式不同，如背景色）。cell_diffs 列出具体差异的单元格坐标（1-based），每个 cell diff 包含 diff_type（modified_content/modified_format）、source_text/target_text（内容差异时）、source_fill_color/target_fill_color（格式差异时，hex 颜色值）。用户可进一步调用 resolve_document_structure 获取表格内部详细结构。性能优化：当一篇文档正文明显更长时，长文档尾部段落不逐段对比。页眉页脚、文本框、批注始终完整对比，不受正文截断影响。
doc_convert_to_html                      将当前打开的 Word 文档正文导出为语义化 HTML（DOC）。返回完整 HTML 文档：<head> 含全局样式，<body> 为语义化标签 + 内联样式，格式保真：标题输出 h1-h6、表格输出 table/tr/td（含 colspan 横向合并、单元格底纹 background-color、边框）、字体输出 font-family/font-size、段落对齐与缩进输出 text-align/text-indent 等内联样式。只导出正文，页眉/页脚不在导出范围。与 doc_insert_html_content 互为逆向操作：本工具 doc→HTML，doc_insert_html_content 为 HTML→doc。【图片说明】默认输出 <img src="docx:/word/media/xxx"> 包内路径占位（不含二进制）；传 image_dir 可把文档引用的图片提取到该目录，src 同步重写为纯文件名（需要 file_id 为 docx 文件路径，本地 open_file 即满足）。【体积提示】大文档 HTML 较大；传 output_path 可将 HTML 写入本地文件，响应只返回路径与大小。
doc_copy_content_from                    复制粘贴（DOC）：从已打开的 DOC 复制任意合法 GCP range，并完整粘贴到当前目标文档的 target_index。当前工具调用的 file_id/file_path 是目标文档；来源通过 source_file_id 或 source_file_path 指定；来源可与目标为同一份文档，但需要移动已有内容时应使用 doc_move_content，避免 copy 后再删源的中间重复状态。source_range 和 target_index 都是 GCP 坐标，应通过 doc_find、doc_resolve_document_structure、doc_get_outline、doc_list_tables/doc_get_table_info、doc_get_last_operable_pos 等查询类工具获取，不要手算。文本框、普通 shape、组合图形、无图资源的空 drawing 壳默认不复制（include_textbox_and_shapes=false）；有 embed 的图片和图表仍复制。批注默认复制（include_comments=true）。页面设置（纸张方向、页宽页高、页边距等）默认随内容保留。样式按名字对应、来源优先：目标已有同名同类型样式时沿用目标样式 id，定义整体换成来源的（目标里其他引用该样式的段落外观随之变化），不会出现同名的第二份样式；目标没有的样式随内容带入。
doc_copy_format                          格式刷（DOC）：将源范围的段落属性和文本属性复制到目标范围。读取 source_range 起始位置处生效的段落格式（对齐、缩进、间距、样式等）和文本格式（加粗、斜体、字号、字体、颜色等），然后应用到 target_ranges 指定的所有范围上。适用于快速统一多个段落/文本的格式。
doc_copy_format_from                     从模板文档拷格式到当前文档（DOC，论文模板套版）：样式 + 直排一起拷，保留模板样式名。取样：source_file_id + source_range 指向模板样本段（run_source_range 可指定样本 run，默认取段内第一个正文字）；或传上次回执里的 format_blob（不必再打开模板）；或 source_file_id + source_style_name 只迁一个命名样式（页眉页脚、表格样式这类样本不在正文段落里的），此时不传 ranges / overlay，只把该样式及依赖链、编号按名字迁入，不改任何段落。三者必须且只能传一个。拷的是原始 OOXML：段落 pStyle 及 basedOn/link/next 链按样式名迁入（已有同名样式整体替换，没有就新建），编号定义在目标里有相同列表就复用（多次调用编号连续），否则新建；样本段 pPr（除分节 / 段前分页 / 修订外）与样本 run rPr 原样写成目标直排，目标原有直排先整体替换（run 上 keep_run_keys 列出的键、脚注引用符保留）。paragraph_overlay / run_overlay 在拷完后以直排覆盖（字段同 doc_register_named_styles）；paragraph_overlay.numbering_type=null 写 numId=0 去编号，outline_lvl 写直排大纲级别。scope：paragraph_and_run（默认，整段）/ paragraph_only（只拷段落格式，段内 run 只清直设）/ run_only（只拷字符格式到 ranges 内的 run）。【示例】{"source_file_id":"template","source_range":{"begin":3120,"end":3140},"ranges":[{"begin":880,"end":905}],"paragraph_overlay":{"outline_lvl":9}}
doc_delete_comment                       删除单条批注（DOC）。`id` 来自 doc_get_comments 返回的批注 id。若同一锚点仍有其他批注或回复，只删除指定批注正文并保留锚点；若这是该锚点的最后一条批注，则同时移除对应的 commentRange/Reference。不会删除被批注的文档正文。删除会改变 DOC 坐标，后续操作请重新获取位置。
doc_delete_footnote                      删除脚注或尾注（正文引用标记 + 页底/文末 substory 正文）。
doc_delete_paragraph                     删除 idx 所在的整个段落（DOC）。只需要传光标所在位置 idx；底层会自动定位该段落的完整范围并删除，包含该段落结束符。idx 必须是 DOC 坐标；不要传 paragraph_index 或手算字符数。删多段须从后往前逐次调用并重新查询 idx；不可删除主文档最后一个段落。
doc_delete_section_break                 删除指定非末节的终止分节符，把该节与后一节合并（节内文字内容不会被删除）。使用 section_id（稳定，推荐）或 section_index（0-based）定位要被合并掉的前一节；都传时 section_id 优先。⚠️ 合并后整段套用分节符**之后**那一节的页面属性（方向/页边距/页眉页脚等），之前那一节的页面设置会被丢弃：回包的 discarded_section_id 是被丢弃设置的节，kept_section_id 是设置生效的节。因此想让某一节的页面设置覆盖它前面那一节时，删它前面那个分节符即可。末节由正文终止符收尾，不能作为删除目标；只改末节页面设置请用 doc_modify_section。删除后节索引会变化，继续按 section_index 操作前应重新查询。
doc_delete_shapes                        按 id 批量删除文本框 / 形状（DOC）。`drawing_ids` 取自 doc_list_text_boxes_shapes 的 `drawing_id`。删除整个 drawing：文本框连同框内文字，分组 / 画布连同全部子形状。一次调用为一次编辑，重复 id 只删一次；任一 id 找不到或不是可列出的对象（如图片、艺术字）则整体报错、不删任何内容。删除会改变 DOC 坐标，后续请重新获取位置。
doc_delete_table                         删除整张表格（DOC）。优先使用 table_id 定位（8字符稳定标识），未提供 table_id 时使用 idx（表格内任意 cell 的 GCP 坐标）。删除后表格后面的内容位置会发生偏移，请谨慎使用删除工具，需要先获取用户确认再使用。
doc_delete_table_column                  删除表格中的一列（DOC）。通过 table_id 或 idx 定位表格（优先 table_id），col 为 1-based 列号。如果删除所有列则整个表格被删除。
doc_delete_table_row                     删除表格中的一行（DOC）。通过 table_id 或 idx 定位表格（优先 table_id），row 为 1-based 行号。如果该行包含 vMerge 合并单元格会自动处理。如果删除所有行则整个表格被删除。
doc_find                                 查找文本所在位置（DOC），返回所有匹配位置的 begin/end 索引、上下文及定位锚点，不跨段落/表格/图片等结构边界。返回的 begin/end 是可直接回填到 doc_replace_text / doc_update_text_property 的 DOC 坐标；不要按肉眼字符数、段落序号或行号手算位置。每个匹配额外返回：related_text（前后各30字上下文，[匹配文本]标记位置）、paragraph_id（可直接传给 doc_modify_paragraph(paragraph_id=)）、table_id/table_index/row/col（匹配在表格内时返回，可直接定位到单元格）。
doc_find_and_replace                     查找并替换文本（DOC）；文本匹配规则与 doc_find 一致，不跨段落/表格/图片等结构边界。可通过 scope 限定替换范围。
doc_find_and_set                         按文本内容 + 文本属性组合查找，对匹配项批量执行替换/改属性/删除（DOC）；文本匹配规则与 doc_find 一致。
doc_get_comments                         获取 DOC 文档中所有批注（DOC）。返回 `total` 与按 range_begin 升序排列的 `comments` 数组，每条包含：`id`（批注 id，与 doc_insert_comment 写入时一致）、`range_begin` / `range_end`（批注锚定范围的字符 idx，与 doc_get_last_operable_pos.position 同坐标系；begin == end 表示零长度的「点锚」批注，对应字段 `is_point_anchor=true`）、`text`（批注正文文本，已过滤其中的图片/表格等复杂内容，与 OOXML 视觉渲染对齐）、`reply_to`（同一对话线程首条批注的 id，仅回复批注才有；底层线程为扁平结构）、`author` / `date`（作者展示名与 Unix epoch 毫秒时间戳字符串，未设置时不返回）。主要用于对 doc_insert_comment 的结果做验证、以及在执行批注相关编辑前枚举现有批注。
doc_get_images                           获取 DOC 文档中所有图片的信息（DOC）。返回数组中每一项包含以下字段：`source` (1 = drawing 嵌入图片，2 = field-attachment 字段附件图片)、`index` (图片在文档中的字符 idx，与 doc_insert_image / doc_replace_image 的 index 、doc_get_last_operable_pos.position 同一坐标系)、`image_url` (本会话的可寻址 URL，doc_replace_image 可拿来作为 old_image_url 使用)。数组按 index 升序返回；“第 N 张图”即为数组下标 +1，无需额外字段。
doc_get_last_operable_pos                获取DOC文档正文最后一个可操作位置的索引，以及该位置前面最多10个字符的内容。在需要向文档末尾追加内容时，可先调用此接口获取末尾可操作位置（DOC）。返回的 position 是可直接传给插入类工具的 DOC 坐标，不是可见字符序号。
doc_get_outline                          获取文档大纲树（DOC）。只返回标题层级结构（Heading 1-9），不包含表格/图片/普通段落等非标题节点。返回树形结构，每项含 title / level / title_start / title_end / content_start / content_end。适用场景：快速了解文档章节结构和定位插入位置。如需获取完整文档结构（含表格 cells、段落、图片等），请用 doc_resolve_document_structure。
doc_get_paragraph_property               读取 DOC 文档指定位置 idx 所在「段落」的属性（与 doc_insert_paragraph 字段对称）：段落样式名（可读，如 heading 1 / Title / Normal）、大纲级别、推断出的 heading_level (1..9, 0=非标题)、是否带编号及编号级别 (1..9)、对齐方式、缩进（pt）、段前/后间距 (pt) 与行距。字段不存在表示未显式设置（继承默认值）。同时回读分页控制（keep_with_next/keep_together/page_break_before/widow_control）、自定义 tab_stops，以及 numbering_restart（当前 num_id 首段=true，续接=false）。主要用于对段落编辑结果做验证。
doc_get_section_property                 读取 DOC 文档指定 section 的基础页面属性。支持 section_id（稳定，推荐）或 section_index（0-based，插删分节符会漂移）二选一定位；都传时 section_id 优先。返回 section_id（若已分配）、section 范围、总节数、页面方向和宽高、页边距、页眉页脚距离、装订线、分节起始类型、是否首页页眉页脚不同，以及文档网格 doc_grid_type / doc_grid_line_pitch / doc_grid_char_space。所有长度统一为 pt。
doc_get_table_info                       获取指定表格的完整信息（DOC）。定位方式三选一（优先级 table_id > idx > table_locate）：① table_id（8 字符稳定标识，取自 doc_list_tables，最推荐）；② idx（表格内任意 GCP）；③ table_locate.cell_match（按单元格文字定位）。手上都没有时先 doc_list_tables 拿 table_id。
doc_get_text_property                    读取 DOC 文档指定位置 idx 处生效的文本属性（与 doc_update_text_property 字段对称）：加粗/斜体/下划线及线型/下划线颜色/单删除线/双删除线/小型大写/颜色/底纹(background_color)/高亮(highlight)/字号(pt)/字体/上下标等。响应中「字段不存在」表示该属性未在 run 上显式设置，应认为「继承自段落 / 样式默认值」。
doc_get_word_art_info                    读取指定位置艺术字的属性。返回字段：wordart_idx（锚点位置）、style（视觉效果名）、text（艺术字文字）、width_px / height_px（外框尺寸）、text_range: {begin, end}（艺术字文字的 GCP range，可传给 doc_update_text_property.ranges 修改字号/颜色/字体等；空框艺术字不返回此字段）。
doc_insert_border                        在指定段落的底部插入分隔线（DOC）。通过设置段落底部边框（pBdr/bottom）来实现水平分隔线效果。支持两种定位方式（二选一）：传 `paragraph_id`（推荐，无需先调 doc_resolve_document_structure）或传 `idx`（分隔线上方段落的 end_index）。二者都传时以 `paragraph_id` 为准。支持多种边框样式和自定义颜色。
doc_insert_comment                       插入批注（DOC）。接口返回中除 last_edit_index 外，还会多带一个 `position` 字段（插入后文档末尾可操作位置），避免调用方为了拿插入后的位置再去调 doc_get_last_operable_pos。说明：批注插入会为文档插入 commentRangeStart/End/Reference 等占位符，文档总长度会增加；后续操作请以 `position` 为准。
doc_insert_footer                        设置页脚文本内容（DOC）。覆盖式写入：先清空已有页脚内容，再写入新文本。空文本会去掉 footer 段落底边框横线（pBdr.bottom=none）。本工具一次只处理一个 section（由 section_index 指定）；section_index / footer_type 与 get_document_content.header_footer.footers[] 的section_index / type 同名。footer_type=even 时会打开文档 evenAndOddHeaders。如需对多个 section 都写入页脚，请按需多次调用本工具。首次插入时会为目标 section 独立创建页眉页脚 substory，打破该 section 与前一节"链接到上一节"的关系。
doc_insert_footnote                      在指定位置插入脚注或尾注（DOC）。脚注显示在页面底部，尾注显示在文档末尾。
doc_insert_header                        设置页眉文本内容（DOC）。覆盖式写入：先清空已有页眉内容，再写入新文本。空文本会去掉页眉底边框横线；有文字且未传 paragraph_border 时写 header 默认单线。paragraph_border.bottom 可指定 pBdr（如模板双线 thinThickSmallGap sz=18）。读回见 header_footer.headers[].paragraph_border（直接边框）；样式上的 pBdr 在 header_footer.styles / 快照 styles。本工具一次只处理一个 section（由 section_index 指定）；section_index 与 get_document_content.header_footer.headers[].section_index、doc_get_section_property 同为 Word 节 0-based。header_type 与 header_footer.headers[].type 同名（default/first/even）。header_type=even 时会打开文档 evenAndOddHeaders（奇偶页不同页眉）；Word 没有该开关会忽略偶数页眉。如需对多个 section 都写入页眉，请按需多次调用本工具。首次插入时会为目标 section 独立创建页眉页脚 substory，打破该 section 与前一节"链接到上一节"的关系。左右分栏页眉用 parts[]（定位制表符 w:ptab，不是普通 tab）。交大两栏示例：左 STYLEREF 主题 + ptab(right) + 右 STYLEREF 标题1；三栏可插 ptab(center) 与 ptab(right)。不要把左右文字拼成一条 text。text_format 写入 header 段落样式默认 rPr（混排请同时给 font_ascii + font_east_asia）；parts[].text_format 可单段覆盖（字号/颜色/加粗等与顶层不同）。含 ptab 时 horizontal_align 被忽略，段落固定左对齐（右栏由 ptab 定位）。paragraph_format 写页眉段落的缩进与间距（w:ind / w:spacing），只写传了的项，其余继续继承 header 样式；读回见 get_document_content.header_footer.headers[].paragraph_format（同单位）。
doc_insert_html_content                  在指定 idx 处插入一段 HTML 富文本（DOC），引擎会按 HTML 标签 / <style> 块内 CSS 规则 / 内联样式自动转为段落、标题、列表、表格、链接、加粗 / 斜体 / 下划线、文字色 / 背景色等富文本元素。本接口为批量解析模式，一次调用可插入多个段落 / 列表 / 表格。
doc_insert_image                         在指定位置插入图片（DOC）。**优先使用 image_path 传本地图片文件的绝对路径**（image file local path；Windows 如 C:\Users\me\a.png，POSIX 如 /home/me/a.png）；这是最省 token、最不易出错的方式。仅当图片确实只存在于内存、没有落盘文件时，才用 content 传 data URI（该形态仍完全支持）。image_path 与 content 二者必填其一（同时传以 image_path 为准）。不支持纯 base64 字符串（请加 data: 前缀），也不支持 http(s) 远程 URL。插入成功后直接返回新图的 image_url，无需再调 doc_get_images 反查。idx 是 DOC 坐标，需来自查询结果或上一次写操作返回值，不要按肉眼位置手算。
doc_insert_markdown                      在指定位置插入 Markdown 格式内容（DOC），支持标题、列表、表格、链接、加粗 / 斜体等常见语法，引擎会自动将 Markdown 转换为文档富文本格式。一次调用可插入多个段落 / 列表 / 表格。

doc_insert_normal_link                   插入普通链接（DOC）。这是在 idx 位置插入一个链接字段，不是给已有文本范围设置链接；显示文本由 text/file_name 决定。idx 是 DOC 坐标，使用查询结果或写操作返回值，不要手算。

doc_insert_section_break                 在指定 DOC/UTF-16 坐标插入分节符。idx 之前的内容保留在前一节，idx 及其后的内容进入后一节；拆分后的前后两节完整继承原节的节级属性，仅后一节的起始类型改为 start_type。段中/段尾插入时，分节前的内容保留原段落属性；段首插入使用干净的结构承载段。不会额外插入段落回车。start_type 可选，默认 new_page。插入后文档坐标和节索引会变化，继续操作前应重新查询。回包给出两节的稳定 id：section_id 是新建的前一节（截止到分节符），next_section_id 是分节符之后那一节（沿用原节 id）——想让分节符后的内容换成横向、改页边距等，用 next_section_id 传给 doc_modify_section。

doc_resolve_document_structure           获取文档结构树（DOC），返回扁平节点列表，用于在调用需要 idx/index/ranges 的写类工具前定位位置。DOC 的 idx/begin/end 是 UTF-16 code unit 坐标，包含段落结束符、表格、图片、字段等结构占位；不要按肉眼字符数、段落序号或行号手算。节点 type：Paragraph / Heading（heading_level 1..9）/ Title / Subtitle / Table；编号段的 numbering_type 与写接口一致，可为 bullet / decimal_comma / task / decimal / bullet_arrow / bullet_hollow_circle / multilevel_decimal / chinese_numbering / upper_letter；文字下划线/删除线/高亮通过 has_highlights 标志位 + highlight_spans 嵌入在 Paragraph 内.

doc_set_highlight_block                  把已有段落设置为一个高亮块（DOC）。通过 paragraph_ids 定位目标段落，paragraph_id 的解析在服务端内部完成，调用方无需感知 GCP 坐标（不会因坐标漂移出错）。paragraph_ids 直接用 doc_insert_paragraph_with_text 回包的 paragraph_id（插入即返回，无需再调 doc_resolve_document_structure）；查历史段落时也可用 doc_resolve_document_structure 的 paragraph_id 字段。高亮块是段落级属性：每个 paragraph_id 对应一个独立的高亮块（一段一个 textbox 容器），不合并区间。多段场景服务端循环逐段转换，每段独立保留自身样式/缩进。对比 doc_modify_paragraph.highlight_block：后者按 GCP ranges 定位且一次只处理第一个 range，本工具按 paragraph_id 定位且天然支持多段（各段独立高亮块）。【示例】{"paragraph_ids":["0F7A3331","0F7A3332"],"bg_color":"FEF8E4","border_color":"FBEBAE"}
doc_set_page_number                      设置页码（在页脚中插入 PAGE 字段）（DOC）。默认参数组合：页面底部右侧 + 1,2,3 格式 + 续前节 + 应用于整篇文档 + 首页也显示页码。调用前会自动切换为分页模式。position / format / continue_from_prev / skip_first_page / text_format / scope 均已支持。scope=whole_doc 处理全部节；from_here 从 section_index 到文末；current_section 仅该节。skip_first_page 默认 false：首页也显示页码。传 true 则文档第一节打开「首页不同的页眉页脚」，首页页脚留空（封面无页码），从第二页起显示 PAGE。它只改第一节，不能用来清掉封面整节页码。绪论才开始有页码时：先在绪论处分节，再 set_page_number(scope=from_here, section_index=绪论节)，并对前面各节 insert_header/insert_footer(text="") 清空。text_format 写入 PAGE 可见文本的字体/字号（与 insert_header 同形，如 {"font_family":"Times New Roman","font_size":9}）。
doc_set_table_cells                      批量设置表格单元格内容与样式（DOC）。凡涉及表格单元格的文本/格式/属性/对齐/超链接/图片修改，都必须用本工具（禁止用 GCP 坐标类工具改表格）。table_id 或 idx 定位表格（优先 table_id），row/col 为 1-based。text 整体替换单元格文本；property 改底色/垂直对齐/边框；text_format 改字体格式；horizontal_align 改段落对齐。多 cell 共用样式时提到 common_cell_properties，cells 只写差异（inherit:false 可跳过公共样式）。合并单元格：mc=true 格自动定位到合并起始格应用格式，文本替换仅对起始格生效。
doc_set_table_properties                 修改表格属性 + 布局（DOC）。通过 table_id 或 idx 定位表格，优先使用 table_id（8字符稳定标识，不随编辑漂移）；未提供 table_id 时使用 idx（表格内任意 cell 的 GCP 坐标）。可同时设置边框、对齐、宽度、单元格内边距、条件染色、垂直对齐、行高、列宽、表格命名样式。全部字段可选，未提供的属性沿用原表格设置。
doc_undo_ai_edit                         撤销指定 version 的 AI 编辑（DOC）。

doc_update_named_style                   修改命名样式的定义（DOC），一次调用立即影响文档中所有使用该样式的段落，无需逐段修改。支持 upsert：内置样式不存在时按 Word 规范自动创建而非报错，因此空白文档里尚未实例化的 TOC 1~TOC 9 也能提前设好，样式可在写正文前一次性配完，之后 doc_insert_toc 会直接套用。paragraph_style 和 text_style 至少传一个；只传需要修改的子字段。【示例·所有H1改为16pt居中】{"named_style_type":"HEADING_1","paragraph_style":{"jc":"center"},"text_style":{"font_size":16}}【示例·正文行距改1.5倍】{"named_style_type":"NORMAL_TEXT","paragraph_style":{"line_spacing":1.5,"line_spacing_rule":1}}【示例·预设二级目录项】{"named_style_type":"TOC 2","paragraph_style":{"left_indent":24},"text_style":{"font_size":10.5}}
doc_update_text_property                 更新指定字符范围内的文本属性（DOC）。仅修改样式，不改变文档内容长度，因此返回值不包含 position 字段（与其他 insert_* 接口不同）。支持加粗、斜体、下划线（含线型/颜色）、单删除线、双删除线、小型大写、文字色、底纹色、高亮、字号、字体、上下标，所有样式字段均为可选，未传的字段保持原样不变。background_color 是底纹颜色，highlight 是高亮文本，二者不同，同时设置时高亮会覆盖底纹。
