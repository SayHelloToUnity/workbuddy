  87→

 100→执行每条命令后，系统会提示设置密码短语。可以设置一个密码（更安全，之后可通过 ssh-agent 避免重复输入），也可以直接回车留空（使用上最省事）。生成完成后，`~/.ssh/` 目录下会多出四个文件：
 101→
 102→```
 103→id_ed25519_github          ← GitHub 私钥（不要外传）
 104→id_ed25519_github.pub      ← GitHub 公钥（上传到平台）
 105→id_ed25519_gitlab          ← GitLab 私钥
 106→id_ed25519_gitlab.pub      ← GitLab 公钥
 107→```
 108→`ed25519` 是目前推荐的密钥算法，比传统的 RSA 更短、更安全，GitHub 和 GitLab 均完整支持[reference:1]。

 126→### 第三步：编写 `~/.ssh/config` 文件（核心步骤）
 127→
 128→这个文件是 OpenSSH 实现多密钥路由的关键。用任意文本编辑器（记事本、VS Code 均可）创建或编辑 `C:\Users\你的用户名\.ssh\config`（如果文件不存在就直接新建）。
 129→
 130→写入以下内容：
 131→
 132→```text
 133→# GitHub — 使用专属密钥
 134→Host github.com
 135→    HostName github.com
 136→    User git
 137→    IdentityFile ~/.ssh/id_ed25519_github
 138→    IdentitiesOnly yes
 139→
 140→# GitLab — 使用专属密钥
 141→Host gitlab.com
 142→    HostName gitlab.com
 143→    User git
 144→    IdentityFile ~/.ssh/id_ed25519_gitlab
 145→    IdentitiesOnly yes
 146→```
 147→
 148→关键字段说明[reference:2]：
 149→
 150→| 字段 | 作用 |
 151→|---|---|
 152→| `Host` | 匹配的别名或域名。这里直接写真实域名，无需额外修改仓库地址 |
 153→| `HostName` | 实际连接的服务器地址（`Host` 写域名时可省略，写上更清晰） |
 154→| `IdentityFile` | 指定该域名使用的**私钥文件路径** |
 155→| `IdentitiesOnly yes` | **强制只使用指定的这一把密钥**，防止 ssh-agent 中加载的其他密钥造成认证混乱 |
 156→
 157→`IdentitiesOnly yes` 在多密钥场景下非常重要，没有它，OpenSSH 可能会尝试用错密钥，导致认证失败或提示权限拒绝。

 785→### 🔑 两种 Key 的区别
 786→*   **Authentication Key (身份验证密钥)**：作用就是**访问仓库**，用于克隆、拉取、推送代码。你目前只需要这个。

 789→简单来说，**选 `Authentication Key` 就能满足你拉取和推送代码的核心需求**。

 792→只有当你或团队有**强制要求**，希望所有Git提交都必须经过密码学签名验证，防止他人伪造你的名义提交代码时，才需要选择这个类型。

1397→
1398→在使用 Git 克隆代码时，通常有两种连接方式：
1399→
1400→1. **Clone with HTTP (HTTPS)**
1401→   - **原理**：使用账号 + 密码（或 Token）进行认证。

1436→```bash
1437→cat > ~/.ssh/config << 'EOF'

1440→    HostName 192.168.1.2
1441→    User git
1442→    IdentityFile ~/.ssh/id_ed25519_gitlab
1443→    IdentitiesOnly yes

1446→Host github.com
1447→    HostName ssh.github.com
1448→    Port 443
1449→    User git
1450→    IdentityFile ~/.ssh/id_ed25519_github
1451→    IdentitiesOnly yes

1464→## 三、 常见报错与避坑指南
1465→
1466→### 1. GitHub 报错：`Connection refused` (连接被拒绝)
1467→- **原因**：国内网络环境下，防火墙或代理经常封锁 SSH 默认的 22 端口。
1468→- **解决**：在 `config` 文件中将 GitHub 的 `HostName` 改为 `ssh.github.com`，并添加 `Port 443`（使用 HTTPS 的端口来跑 SSH，通常会放行）。
1469→
1470→### 2. 报错：`garbage at end of line; "#"`
1471→- **原因**：`config` 文件行尾出现了不被支持的注释（如 `Port 443 #这是端口`）。
1472→- **解决**：删掉行尾的 `#` 及后面的文字。注释只能单独占一行。
1473→
1474→### 3. 报错：SSH 一直提示输入密码 `git@...'s password:`
1475→- **原因 1**：`config` 文件没被读取（可能存成了 `config.txt`，或者权限不对）。
1476→- **原因 2**：服务端没有正确添加公钥。
1477→- **排查命令**：
1478→  - 检查配置是否生效：`ssh -G git@192.168.1.2 | grep identityfile`
1479→  - 调试详细过程：`ssh -vT git@192.168.1.2`
1480→  - 强制指定私钥测试：`ssh -i ~/.ssh/id_ed25519_gitlab -o IdentitiesOnly=yes -T git@192.168.1.2`
1481→
1482→### 4. 关于 HTTP 的“幽灵密码”
1483→如果旧项目以前用 HTTP 克隆，现在不改地址也能正常拉取。这是 **Windows 凭据管理器** 在起作用。如果想彻底拥抱 SSH，需要手动修改远程仓库地址。

1710→ssh-keygen -t ed25519 -C "你的GitLab邮箱" -f ~/.ssh/id_ed25519_gitlab
1711→
1712→# 为 GitHub 生成
1713→ssh-keygen -t ed25519 -C "你的GitHub邮箱" -f ~/.ssh/id_ed25519_github
1714→```
1715→
1716→### 2. 添加公钥到平台
1717→将生成的 `.pub` 文件内容复制到对应网站（`GitLab -> Settings -> SSH Keys`，`GitHub -> Settings -> SSH and GPG keys`）。

1719→```bash
1720→# 复制 GitLab 公钥到剪贴板
1721→clip < ~/.ssh/id_ed25519_gitlab.pub
1722→
1723→# 复制 GitHub 公钥到剪贴板
1724→clip < ~/.ssh/id_ed25519_github.pub
1725→```
1726→
1727→### 3. 编写核心 `config` 文件（实现多平台路由）
1728→在 `~/.ssh/` 目录下创建 `config` 文件（**千万不要带 .txt 后缀**）。
1729→*最稳妥的创建方式（用命令行直接生成，避免记事本后缀名问题）：*
1730→```bash
1731→cat > ~/.ssh/config << 'EOF'
1732→# 公司内网 GitLab
1733→Host 192.168.1.2
1734→    HostName 192.168.1.2
1735→    User git
1736→    IdentityFile ~/.ssh/id_ed25519_gitlab
1737→    IdentitiesOnly yes
1738→
1739→# 公网 GitHub (绕过 22 端口)
1740→Host github.com
1741→    HostName ssh.github.com
1742→    Port 443
1743→    User git
1744→    IdentityFile ~/.ssh/id_ed25519_github
1745→    IdentitiesOnly yes
1746→EOF
1747→```
1748→**⚠️ 注意：** `config` 文件中 `Port 443` 等配置项**绝对不能**在行尾写 `# 注释`，否则会报错 `garbage at end of line`。

1792→## 四、 常见报错与避坑指南
1793→
1794→### 1. GitHub 报错：`Connection refused` (连接被拒绝)
1795→- **原因**：国内网络环境下，防火墙或代理经常封锁 SSH 默认的 22 端口。
1796→- **解决**：在 `config` 文件中将 GitHub 的 `HostName` 改为 `ssh.github.com`，并添加 `Port 443`（使用 HTTPS 的端口来跑 SSH，通常会放行）。
1797→
1798→### 2. 报错：`garbage at end of line; "#"`
1799→- **原因**：`config` 文件行尾出现了不被支持的注释（如 `Port 443 #这是端口`）。
1800→- **解决**：删掉行尾的 `#` 及后面的文字。注释只能单独占一行。
1801→
1802→### 3. 报错：SSH 一直提示输入密码 `git@...'s password:`
1803→- **排查 1**：检查 `config` 文件是否没被读取（参考“第三部分”的验证步骤）。
1804→- **排查 2**：服务端没有正确添加公钥，或添加成了私钥。
1805→- **排查 3**：权限过高，运行 `chmod 600 ~/.ssh/config` 和 `chmod 600 ~/.ssh/id_ed25519_gitlab`。
1806→- **高级排查命令**：`ssh -vT git@192.168.1.2`（查看详细握手日志），或强制指定私钥 `ssh -i ~/.ssh/id_ed25519_gitlab -o IdentitiesOnly=yes -T git@192.168.1.2`。
1807→
1808→### 4. 关于 HTTP 的“幽灵密码”
1809→如果旧项目以前用 HTTP 克隆，现在不改地址也能正常拉取。这是 **Windows 凭据管理器** 在起作用。如果想彻底拥抱 SSH，需要手动修改远程仓库地址。
