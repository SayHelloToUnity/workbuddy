版）\n\n本文档记录了 Git 环境搭建、多平台（GitLab/GitHub）SSH 共存配置、如何验证配置是否生效，以及常见网络/语法报错的避坑指南。适用于 Windows + TortoiseGit + Git Bash 环境。\n\n---\n\n## 目录\n\n- [一、核心概念：HTTP vs SSH](#一核心概念http-vs-ssh)\n- [七、附录：一键排查命令汇总](#七附录一键排查命令汇总)\n\n---\n\n## 一、核心概念：HTTP vs SSH\n\n在使用 Git 克隆代码时，通常有两种连接方式：\n\n1. **Clone with HTTP (HTTPS)**\n   - **原理**：使用账号 + 密码（或 Token）进行认证。\n   - **特点**：Windows 的\"凭据管理器\"会自动记住密码，所以配置简单。但密码更改或 Token 过期时容易报错，且大文件传输效率不如 SSH。\n2. **Clone with SSH（推荐）**\n   - **原理**：使用非对称加密（公钥 + 私钥）。你将公钥放到服务器上，私钥留在自己电脑里。每次连接时，双方自动验证。\n   - **特点**：免密操作，安全高效。同一台电脑可以利用 `config` 文件，为不同平台（如公司内网 GitLab 和公网 GitHub）配置不同的密钥。\n\n> **关键认知**：TortoiseGit 是一个通用 Git 图形客户端，只认「仓库 URL」，不认平台。GitLab 与 GitHub 的区别仅在于地址与认证方式，二者可同时使用。\n\n---\n\n## 二、基础配置流程（生成密钥与路由）\n\n### 1. 生成 SSH 密钥\n\n打开 **Git Bash**，为不同平台分别生成独立的密钥（推荐使用 `ed25519` 算法，比 RSA 更安全、更短）。在命令行中输入以下命令，遇到提示一路按回车（跳过密码设置，避免每次操作都要输入密码）。\n\n```bash\n# 为 GitLab 生成\nssh-keygen -t ed25519 -C \"你的GitLab邮箱\" -f ~/.ssh/id_ed25519_gitlab\n\n# 为 GitHub 生成\nssh-keygen -t ed25519 -C \"你的GitHub邮箱\" -f ~/.ssh/id_ed25519_github\n```\n\n执行成功后，`~/.ssh/` 目录下会得到四个文件：\n\n```text\nid_ed25519_gitlab          私钥（不可外传）\nid_ed25519_gitlab.pub      公钥（上传到 GitLab）\nid_ed25519_github          私钥（不可外传）\nid_ed25519_github.pub      公钥（上传到 GitHub）\n```\n\n> 出现方形的 `randomart image` 图案，即为生成成功的标志。\n\n### 2. 添加公钥到平台\n\n将生成的 `.pub` 文件内容复制到对应网站（`GitLab -> Settings -> SSH Keys`，`GitHub -> Settings -> SSH and GPG keys`）。\n\n*快捷复制命令（直接写入剪贴板，避免鼠标选区出错）：*\n\n```bash\n# 复制 GitLab 公钥到剪贴板\nclip < ~/.ssh/id_ed25519_gitlab.pub\n\n# 复制 GitHub 公钥到剪贴板\nclip < ~/.ssh/id_ed25519_github.pub\n```\n\n> GitHub 添加密钥时，**Key type 保持默认的 `Authentication Key` 即可**。`Signing Key` 用于给提交签名（显示 Verified 徽章），普通拉取/推送不需要。\n\n### 3. 编写核心 `config` 文件（实现多平台路由）\n\n在 `~/.ssh/` 目录下创建 `config` 文件（**千万不要带 .txt 后缀**）。\n\n*最稳妥的创建方式（用命令行直接生成，避免记事本后缀名问题）：*\n\n```bash\ncat > ~/.ssh/config << 'EOF'\n# 公司内网 GitLab\nHost 192.168.1.2\n    HostName 192.168.1.2\n    User git\n    IdentityFile ~/.ssh/id_ed25519_gitlab\n    IdentitiesOnly yes\n\n# 公网 GitHub (绕过 22 端口)\nHost github.com\n    HostName ssh.github.com\n    Port 443\n    User git\n    IdentityFile ~/.ssh/id_ed25519_github\n    IdentitiesOnly yes\nEOF\n```\n\n**⚠️ 注意：** `config` 文件中 `Port 443` 等配置项**绝对不能**在行尾写 `# 注释`，否则会报错 `garbage at end of line`。\n\n| 字段 | 作用 |\n|---|---|\n| `Host` | 匹配的别名或域名；此处直接写真实域名/IP，克隆时无需修改地址 |\n| `HostName` | 实际连接的服务器地址 |\n| `Port` | 连接端口，GitHub 用 443 规避 22 端口封锁 |\n| `IdentityFile` | 该域名使用的**私钥**路径 |\n| `IdentitiesOnly yes` | 强制只用指定密钥，防止 ssh-agent 中其他密钥干扰认证 |\n\n> 若公司 GitLab 是自定义域名（如 `gitlab.mycompany.com`），把 GitLab 段的 `Host` 与 `HostName` 同步替换为真实域名。\n\n### 4. TortoiseGit 环境设置\n\n必须让 TortoiseGit 使用 Git 自带的 OpenSSH 引擎，才能读取上述 `config` 文件（`TortoiseGitPlink.exe` 不读取 `~/.ssh/config`）。\n\n1. 右键 -> **TortoiseGit -> Settings** -> **Network**。\n2. 将 **SSH client** 修改为：\n   `C:\\Program Files\\Git\\usr\\bin\\ssh.exe`\n\n> 不确定路径时，在 Git Bash 执行 `where ssh` 获取实际路径后复制。\n\n---\n\n## 三、关键验证与排查步骤（切勿跳过）\n\n配置写好后，必须进行以下验证，确保文件存在且被正确读取。**这一步是本流程中最容易被忽略、也最容易出问题的环节。**\n\n### 1. 验证 `config` 文件是否创建成功\n\n很多新手用记事本保存时，系统会默认加上 `.txt`，或者保存到了别的目录，导致文件失效。在 Git Bash 中运行：\n\n```bash\ncat ~/.ssh/config\n```\n\n- **成功**：终端会打印出你刚刚写入的所有配置文本。\n- **失败**：若报错 `No such file or directory`，说明文件没有创建成功，请重复「二、第 3 步」用命令生成。\n\n> 用记事本保存时，\"保存类型\"必须选择「所有文件 (*.*)」，文件名直接写 `config`，否则会变成 `config.txt`。\n\n### 2. 验证 SSH 是否读取了配置路由\n\n用以下命令检查 SSH 实际生效的密钥路径：\n\n```bash\nssh -G git@192.168.1.2 | grep identityfile\n```\n\n- **成功**：应输出类似 `identityfile ~/.ssh/id_ed25519_gitlab`。\n- **失败**：若输出了 `id_rsa`、`id_dsa`、`id_ecdsa`、`id_ed25519` 等默认密钥，说明 `config` 文件没有被读取，检查文件名、后缀与权限。\n\n### 3. 测试连通性\n\n```bash\n# 测试内网 GitLab\nssh -T git@192.168.1.2\n\n# 测试公网 GitHub\nssh -T git@github.com\n```\n\n*首次连接会提示 `Are you sure you want to continue connecting (yes/no/[fingerprint])?`，输入完整的 `yes` 并回车即可。*\n\n只要看到 `Welcome to GitLab, @xxx!` 或 `Hi xxx! You've successfully authenticated...`，即代表彻底打通。GitHub 返回的 `but GitHub does not provide shell access` 属正常提示，不影响拉取与推送。\n\n---\n\n## 四、常见报错与避坑指南\n\n### 1. GitHub 报错：`Connection refused`（连接被拒绝）\n\n- **原因**：国内网络环境下，防火墙或代理经常封锁 SSH 默认的 22 端口。\n- **解决**：在 `config` 文件中将 GitHub 的 `HostName` 改为 `ssh.github.com`，并添加 `Port 443`（用 HTTPS 的端口跑 SSH，通常会被放行）。\n- **快速验证**：`ssh -T -p 443 git@ssh.github.com`\n\n### 2. 报错：`garbage at end of line; \"#\"`\n\n- **原因**：`config` 文件行尾出现了不被支持的注释（如 `Port 443 #这是端口`）。\n- **解决**：删掉行尾的 `#` 及后面的文字。**注释只能单独占一行**。\n\n### 3. 报错：SSH 一直提示输入密码 `git@...'s password:`\n\n- **排查 1**：检查 `config` 文件是否没被读取（参考「第三部分」的验证步骤）。\n- **排查 2**：服务端没有正确添加公钥，或误把私钥内容粘贴进去。\n- **排查 3**：权限过高，运行 `chmod 600 ~/.ssh/config` 和 `chmod 600 ~/.ssh/id_ed25519_gitlab`（Windows 下还需在文件属性 -> 安全 -> 高级中移除其他用户权限）。\n- **高级排查命令**：`ssh -vT git@192.168.1.2`（查看详细握手日志），或强制指定私钥 `ssh -i ~/.ssh/id_ed25519_gitlab -o IdentitiesOnly=yes -T git@192.168.1.2`。\n- **日志判读**：若输出中没有 `Reading configuration data` 行，说明 `config` 未被加载；若 `Authentications that can continue:` 中只有 `password`，说明服务端未启用公钥认证。\n\n### 4. 关于 HTTP 的\"幽灵密码\"\n\n如果旧项目以前用 HTTP 克隆，现在不改地址也能正常拉取。这是 **Windows 凭据管理器** 在起作用——首次输入账号密码后被静默保存。\n\n**结论：老项目只要能正常拉取提交，不必强行改造**；新项目统一使用 SSH 更省心。若哪天密码变更导致 `Authentication failed`，再用下方命令切换为 SSH 即可。\n\n### 5. TortoiseGit 设置项位置辨析\n\n- **全局 Settings -> Network**：设置 SSH client 引擎（本流程需要改这里）。\n- **项目级 Settings -> Git -> Remote**：为单个仓库指定 URL 与 PuTTY Key。全局设置中**不存在** `Remote` 选项，需在已克隆的项目文件夹内右键打开。\n\n---\n\n## 五、实战操作：切换项目远程地址\n\n对于已经用 HTTP 克隆到本地的老项目（如大型 Unity 工程），**不需要重新克隆**，只需修改 `.git` 里的远程地址即可，且不会影响本地任何代码文件。\n\n1. 打开项目文件夹，空白处右键 -> **Git Bash Here**。\n2. 输入命令替换远程地址：\n\n   ```bash\n   git remote set-url origin git@192.168.1.2:client-group/你的项目名.git\n   ```\n\n3. 检查是否修改成功：\n\n   ```bash\n   git remote -v\n   ```\n\n4. 在项目文件夹中右键 -> **TortoiseGit -> Pull** 验证：若无弹窗直接拉取成功或提示 `Already up to date`，说明 SSH 已生效。\n\n**图形界面等价的三种入口**：\n\n- 项目内右键 -> TortoiseGit -> Settings -> Git -> Remote，修改 `URL`，`Putty Key` 留空。\n- Settings -> Git 页 -> `Edit local .git/config`，直接改 `[remote \"origin\"]` 下的 `url`。\n- 命令行 `git remote set-url`（最快）。\n\n> **Unity 项目提醒**：`.gitignore` 中务必忽略 `Library`、`Temp`、`Logs`、`obj` 等目录，否则仓库体积会迅速膨胀。\n\n---\n\n## 六、多台电脑的密钥管理原则\n\n- **私钥绝对不外传**：公司电脑和家里电脑**绝对不要**互相拷贝私钥文件（`id_ed25519_github` 无后缀的那个）。\n- **各自生成，分别绑定**：每台新电脑都重新执行 `ssh-keygen` 生成独立的密钥对，然后去 GitHub/GitLab 网页端添加公钥（可以起名为 `Work-PC` 和 `Home-PC`）。这样不仅安全，如果某台电脑丢失，只需在网页端删除对应的公钥即可，不影响其他电脑使用。\n- **家里连内网**：如需在家访问公司内网 GitLab，必须先连公司 VPN，并在家中的 `config` 文件里添加内网 IP 的路由配置。\n\n**家庭电脑（仅需 GitHub）极简流程**：\n\n```bash\n# 1. 生成密钥\nssh-keygen -t ed25519 -C \"你的GitHub邮箱\" -f ~/.ssh/id_ed25519_github\n\n# 2. 复制公钥并添加到 GitHub\nclip < ~/.ssh/id_ed25519_github.pub\n```\n\n```text\n# 3. 写入 ~/.ssh/config（直接使用 443 端口，跳过被封锁的 22 端口）\nHost github.com\n    HostName ssh.github.com\n    Port 443\n    User git\n    IdentityFile ~/.ssh/id_ed25519_github\n    IdentitiesOnly yes\n```\n\n```bash\n# 4. 测试\nssh -T git@github.com\n```\n\n---\n\n##
